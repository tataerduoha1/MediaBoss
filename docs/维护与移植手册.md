# MediaBoss 维护与移植手册

面向长期运维：数据字典、性能维护、备份/移植、初始化、故障排查。

---

## 1. 数据字典（存储全景）

MediaBoss 的所有数据集中在 `data/` 目录（可用 `--data-dir` 或 `config.toml` 改位置）。按生命周期分为三类：

### 1.1 总览表

| 数据 | 类型 | 位置 | 作用 | 大小量级 | 清除方式 | 重建方式 |
|------|------|------|------|----------|----------|----------|
| SQLite 数据库 | **长期** | `data/mediaboss.db`（+ `-wal`/`-shm`） | 全部结构化数据：视频索引、JAV 元数据、演员/厂商/系列/类别、观看历史、评分、标签、设置、会话、下载任务 | 10–50 MB（万级影片） | 不可直接删除；用「压缩数据库」瘦身；「工厂重置」清空 | 元数据可重新刮削；索引需重新扫描 |
| 封面与头像 | 缓存 | `data/covers/` | 影片封面、演员头像 | 每张 20–80 KB | 设置 → 数据管理 → 清除（或 API） | 重新刮削自动重新下载 |
| 视频缩略图 | 缓存 | `data/thumbs/` | 无封面视频的列表缩略图 | 每张 5–15 KB | 同上 | 后台 ffmpeg 自动补齐 |
| 自选海报 | **长期** | `data/thumbs/custom/` | 详情页「🖼 自选海报」生成的用户自定义封面（接管封面显示与 NFO 导出） | 每张 30–80 KB | 详情页「恢复默认封面」 | 不可自动重建（用户资产，随一键备份打包） |
| 海报抽帧缓存 | **临时** | `data/thumbs/frames/` | 自选海报的等分抽帧 JPEG（按视频+等分数缓存） | 每张 20–60 KB | 随时可清，无风险 | 再次打开选择器自动重建 |
| 进度条雪碧图 | 缓存 | `data/sprites/` | 播放页进度条悬停预览（10×10 帧拼图） | 每片 100–400 KB | 同上 | 后台 ffmpeg 自动补齐 |
| 用户截图 | **长期** | `data/screenshots/` | 播放中手动截图（用户资产） | 每张 0.1–1 MB | 数据管理 → 清除（**不可恢复**） | 不可恢复 |
| 网络缓存 | **临时** | `data/cache/` | 刮削过程临时文件、下载中间产物 | 通常 <100 MB | 随时可清，无风险 | 按需自动重建 |
| 运行日志 | **临时** | `data/logs/mediaboss.log` | 服务日志（排查问题用） | 数 MB，持续追加 | 随时可清 | 持续写入 |
| ffmpeg 工具 | **长期** | `data/bin/` | ffmpeg / ffprobe 可执行文件（首次自动下载） | ~100 MB | 不可清除 | 删除后到设置页重新「安装 ffmpeg」 |

### 1.2 数据库内部结构（SQLite）

- 文件格式：WAL 模式（读写并发好，`-wal`/`-shm` 是伴随文件，**备份时要一并复制**或先做 checkpoint）。
- 版本迁移：`PRAGMA user_version` 管理结构升级，程序启动时自动执行，**升级无需人工干预**。
- 主要表：`videos`（文件与播放状态）、`jav`（番号元数据）、`actresses` / `studios` / `series` / `genres`（实体）、`jav_actresses` / `jav_genres`（关联）、`watch_history`（播放记录）、`play_log`（播放流水，年度报告/热力图数据源）、`video_tags`（标签）、`collections` / `collection_items`（片单）、`sessions` / `api_tokens`（认证）、`settings`（运行配置）、`directories`（媒体目录）、`downloads`（下载任务）。
- 刮削状态字段 `videos.scrape_status`：`0` 待处理 / `1` 成功 / `2` 失败（重试 3 次后终态）/ `3` 无番号跳过；`next_retry_at` 控制失败重试冷却。

### 1.3 哪些数据能随便动？（速查）

- ✅ **随时可安全清除**：`cache/`、`logs/`
- ✅ **可清除但有代价**（自动重建）：`covers/`、`thumbs/`、`sprites/`——代价是重新刮削/重新生成，产生网络与 CPU 开销
- ⚠️ **谨慎**：`screenshots/`（清了就没了）
- ❌ **不要动**：`mediaboss.db*`、`bin/`（服务运行时直接删除数据库会损坏数据）

## 2. 数据管理操作（设置 → 🗄 数据管理）

界面按钮与对应 API（`POST /api/data/...`，可脚本化）：

| 操作 | 作用 | 适用场景 | API |
|------|------|----------|-----|
| 数据字典 | 查看 8 类数据的类型/大小/数量/作用 | 日常巡检 | `GET /api/data/dict` |
| 清除缓存 | 按类型清除（covers/thumbs/sprites/cache/logs/screenshots） | 磁盘紧张、封面想重下 | `POST /api/data/clear {"targets":[...]}` |
| 压缩数据库 | WAL checkpoint + VACUUM + ANALYZE | 删除大量数据后、数据库虚胖（曾实测 4.4 MB → 536 KB） | `POST /api/data/optimize` |
| 重置刮削状态 | 全部影片标记为待刮削 | 想全量重刮前手动触发（一般用「全量更新」即可） | `POST /api/data/reset-scrape` |
| 工厂重置 | 清空所有表 + 缓存文件，恢复初始状态（需输入 `RESET` 确认） | 转让/换库/彻底重来；**媒体文件不受影响** | `POST /api/data/factory-reset {"confirm":"RESET"}` |

另有 v1.2.0 新增的**一键备份 / 恢复**（设置 → 数据管理）：

| 操作 | 作用 | API |
|------|------|-----|
| 下载数据备份 | 打包数据库（自动 checkpoint）+ 封面 + 自定义海报为 zip 下载 | `GET /api/system/backup` |
| 恢复备份 | 上传备份 zip 覆盖现有数据（需 `?confirm=RESTORE` 参数二次确认），完成后自动重启提示 | `POST /api/system/restore` |

设置 → 关于的「🔍 检查更新」对应 `GET /api/system/check-update`（查询 GitHub Releases，无 Release 时优雅降级提示）。

## 3. 性能与服务器负担

系统内置的节流设计（默认即合理，无需调整）：

- **扫描**：定时自动扫描最低间隔 5 分钟（`scan_interval_min`），单次扫描增量比对、毫秒级完成。
- **刮削**：并发 2，单请求超时 15 s，失败重试最多 3 次，重试冷却默认 15 分钟（`scrape_retry_cooldown_min`），终态不再重试。源站返回明确 404（番号不存在）时**首次即标记终态**，不进入重试循环；HTTP 4xx 请求不做无意义重试。
- **翻译**：单队列串行，不并发打翻译服务。
- **缩略图**：可配并发（`thumb_workers`，默认 2），低配机器可调 1。
- **HTTP**：ThreadingHTTPServer 每请求一线程；静态资源 ETag 304；视频流支持 Range 按需读取，不整文件载入内存。
- **转码播放**：编码不兼容时才启动 ffmpeg 实时转码（每路一路程 + 一个 ffmpeg 子进程），视频编码兼容时仅封装层拷贝（近零 CPU）；浏览器断开（暂停/拖动/切页）即自动 kill 子进程，同一视频重新拉流会先杀旧进程，无僵尸进程堆积。probe 结果按文件 mtime 缓存，重复播放不重复探测。
- **判定精度**：判定基于 ffprobe 实际编码而非扩展名。主视频流选择会跳过 mp4 内嵌封面图流（`attached_pic`，否则会误把封面当视频判定）、优先 default disposition、否则取时长最长流；H.264 额外校验 `pix_fmt`（仅 `yuv420p`/`yuvj420p` 可直连，动画常见的 10bit `yuv420p10le` 自动转码）；**TS 容器**（`format_name=mpegts`，含扩展名 .mp4 的"假 MP4"）一律强制视频重编码——Chrome 无法解封装 TS（直连报 `DEMUXER_ERROR_COULD_NOT_OPEN`），且 TS 内 H.264/AAC 封装拷贝会秒断（音频 ADTS 流拷入 MP4 需加 `-bsf:a aac_adtstoasc`，否则报 "Malformed AAC bitstream detected"）。前端转码模式进度条总长固定用元数据时长（转码流是边转边播的 fMP4，`video.duration` 会随进度增长或为 Infinity，不可直接用；播放位置 = start 偏移 + 流内位置）；`ended` 事件带假结束保护（实际位置 < 元数据时长 90% 时视为流中断，弹「↻ 重试转码」而非报播放结束）。

容量参考：250 部影片时数据库 <1 MB、全套缓存 <200 MB；万级影片预计数据库 10–30 MB。

## 4. 备份

**最省事的方式**：设置 → 「📦 下载数据备份」，一键下载包含数据库 + 全部封面 + 自定义海报的 zip；换机 / 重装时「♻️ 恢复备份」上传即可完整还原（媒体文件路径不变时播放与扫描无缝衔接）。下述手工方式适合脚本化 / 大库场景。

**最小备份集**（还原 = 元数据全保留）：

```
data/mediaboss.db        # 数据库（含 -wal/-shm 一起拷，或先压缩数据库再拷单文件）
config.toml              # 如有自定义
```

**完整备份**（还原 = 免重新刮削，含截图）：

```
整个 data/ 目录（可排除 cache/ 和 logs/）
```

备份时机建议：大批量整理/删除后、版本升级前、定期每周（可加计划任务调用 `POST /api/data/optimize` 后复制 db 文件，用 API 令牌认证）。

## 5. 移植到其他服务器 / 电脑

MediaBoss 零依赖，移植只需 **Python 3.11+**。

**方式 A：连同数据一起搬（推荐）**

1. 旧机：停止服务，打包 `MediaBoss/` 整个目录（或至少 `app/` + `server.py` + `data/` + `config.toml`）。
2. 新机：解压到任意目录，确认装有 Python 3.11+。
3. 启动 `python server.py`（Linux 服务器建议 `nohup python3 server.py --no-browser &` 或注册 systemd 服务）。
4. 媒体文件路径变了怎么办：进「设置 → 媒体目录」，删除旧路径、添加新路径，扫描时系统按文件属性自动识别已入库的视频，不会重复（若同一文件换了盘符/目录，删旧目录重新添加后会按「大小+时长」匹配已有记录）。

**方式 B：只搬程序、重新开始**

只拷 `app/` + `server.py`（不含 `data/`），首次启动自动初始化，重新添加目录、重新刮削。

**注意事项**

- `data/bin/` 里的 ffmpeg 是按平台下载的，跨操作系统移植请删除该目录，启动后到设置页重新「安装 ffmpeg」。
- 局域网访问：新机首次启动放行防火墙（Windows 弹窗选「允许」；Linux 按需 `ufw allow 8656`）。
- 移动端访问：`http://<新机IP>:8656`。

### systemd 服务示例（Linux 常驻）

```ini
# /etc/systemd/system/mediaboss.service
[Unit]
Description=MediaBoss
After=network.target

[Service]
WorkingDirectory=/opt/MediaBoss
ExecStart=/usr/bin/python3 server.py --no-browser
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

`systemctl enable --now mediaboss` 即可。

## 6. 初始化（全新部署 / 重置）

- **全新安装**：直接 `python server.py`，自动建库建目录；浏览器打开后用默认密码 `admin` 登录，第一步改密码，第二步「设置 → 媒体目录」添加目录，第三步点「🔄 更新」开始首次刮削。
- **保留数据重置界面配置**：清除 `data/cache/`、`data/logs/` 即可，无风险。
- **彻底重置**：设置 → 数据管理 → 工厂重置（输入 `RESET`）；或停止服务后删除整个 `data/` 目录。
- **只重置刮削**：数据管理 → 重置刮削状态，然后「🔄 更新」选全量。

## 7. 故障排查

| 现象 | 排查步骤 |
|------|----------|
| 页面空白/白屏 | 1) `Ctrl+Shift+R` 强刷（系统已内置自动强刷一次的自愈逻辑）；2) 看 F12 控制台报错；3) 确认服务进程存活（`/api/system/ping` 返回 pong） |
| 打不开页面 | 端口被占（`-port 9000` 换端口）；防火墙拦截；服务未启动（看 `data/logs/mediaboss.log`） |
| 手机访问不了 | 服务器与手机是否同一网段；防火墙；`config.toml` 是否设置了 `host="127.0.0.1"`（改回 `""`） |
| 扫描不到新文件 | 目录路径是否正确（设置 → 媒体目录）；文件扩展名是否支持（mp4/mkv/wmv/avi/ts 等） |
| 刮削全失败 | 网络能否访问 javbus（必要时设置代理）；失败明细在更新对话框可展开查看 |
| 刮削部分失败 | 正常现象，冷却后自动重试；确认无效番号会被标记「无番号」跳过 |
| 封面不显示 | 数据管理 → 清除 covers → 重新刮削 |
| 播放卡顿 | 大文件高码率建议有线网络；或用 mpv 外播（详情页按钮） |
| 转码播放失败 / 无 ⚡ 徽标 | 1) 设置页确认 ffmpeg 已安装（探测路径存于 `settings` 表 `ffmpeg_path`，也可自动下载到 `data/bin/`）；2) 看 `data/logs/mediaboss.log` 中「转码播放」日志确认模式（v=copy/encode）；3) ffprobe 探测失败的文件按可直播兜底（直连原文件），此时若播放失败可点错误提示中的「⚡ 尝试转码播放」强制转码 |
| MP4 直连却播不了 | 多为编码变体超出浏览器支持（如 H.264 10bit、内嵌封面流干扰判定）；1.4.1 已修复 probe 精度（pix_fmt 校验 + attached_pic 跳过），旧库若仍命中可点「⚡ 尝试转码播放」 |
| 转码刚开始就提示"播放结束"（秒播完） | 文件是 TS 容器的"假 MP4"（下载站常见，ffprobe `format_name=mpegts` 可确认）：直连与封装拷贝均不可行，1.4.1 已修复（TS 强制视频重编码 + 音频 `aac_adtstoasc` 位流过滤）。若仍复现：`Ctrl+Shift+R` 强刷页面，并确认服务进程已重启到新代码（看 `data/logs/mediaboss.log` 转码模式应为 v=encode） |
| 转码拖动进度等待久 | 软编码（H.265→H.264）重启转码需数秒，属正常；拖动频繁可稍等画面恢复再拖 |
| 界面颜色异常 / 主题不生效 | `Ctrl+Shift+R` 强刷；主题保存在数据库 `settings` 表 `theme` 字段与浏览器 `localStorage.mb_theme`（本地优先），设置 → 界面重新选择一次即可同步 |
| 数据库变大 | 数据管理 → 压缩数据库 |
| 手机竖屏播放时部分控制按钮看不到 | 1.4.1 已修复（≤640px 自动隐藏静音/画中画/快捷键帮助，≤480px 收紧间距 + 换行兜底）；若仍复现，手机端清除该站点缓存或从主屏幕移除 PWA 后重开 |
| 手机端 / 局域网设备看不到「🖥 mpv」按钮 | 设计如此：mpv 唤起的是**服务器电脑**上的外部播放器，远端触发会在服务器屏幕弹窗。1.4.1 起仅服务器本机（localhost/127.0.0.1）访问时显示，后端 `/videos/{id}/mpv` 对远端 IP 一律 403（双栈监听下需识别 `::ffff:` 前缀的 IPv4-mapped 地址，见 `httpd.Request.is_localhost`） |
| 视频库格式筛选选不出任何东西 | 1.4.1 已修复：入库 ext 带点（`.mp4`）而下拉值无点，比较永不相等；筛选端点现统一归一化为带点比较（`videos.list_videos`）。若自定义库仍有异常，可对比 `/api/videos?ext=mp4` 的 total 与页面计数 |
| 本地改了文件名，搜索还是旧名字 | 1.4.1 已修复：增量扫描的"改名/移动识别"（指纹命中）此前只同步路径，未同步 filename/title；现一并更新。改名后可在目录页点「立即扫描」或等下轮增量 |
| 同一视频复制到另一目录，库里只出现一份 / 重复检测发现不了 | 1.4.1 已修复：此前指纹命中即当作"移动"处理（原记录被顶替）；现原路径仍在盘上时按"同内容多份拷贝"各自入库（指纹加序号后缀绕开 UNIQUE），重复检测按番号/大小+时长正常命中 |
| 目录禁用再启用后视频/封面/刮削数据丢失 | 1.4.1 已修复：此前禁用目录后首轮增量扫描把其记录当"文件消失"删除；现删除阶段跳过禁用目录，记录原样保留。**已删数据的恢复**：重新启用目录后全量扫描重新入库+重刮 |
| 刮削源被墙 / 换域名后刮不出 | 6 源域名统一在设置→刮削→「源域名列表」配置（格式 `javbus=域名,dmm=域名`，存 settings 表 `scrape_domains`；离散 `{源名}_base` 优先级更高，留空用默认）。启用新源需在「数据源顺序」追加；无效源名日志告警、失败自动换下一源、命中记「刮削命中 via 源名」。多数源直连被反爬（403/JS/CF 526），需配代理。解析失效需升级版本适配（`scraper/*.py`，域名解析统一走 `base.base_of()`） |
| 下载功能（CD2）哪里去了 | 1.4.1 按需求移除：导航入口、设置组、`api/downloads.py`、`services/downloads.py`、前端 downloads.js 已删；DB 中 downloads 表保留无害 |
| 设置里填的值保存后又变空 | 1.4.1 已修复：设置保存有 SAFE_KEYS 白名单（`settings_api.py`），新键 `scrape_domains` 与 6 个 `{源名}_base` 此前不在名单内被静默丢弃；已补齐。新增设置键必须加入 SAFE_KEYS，否则前端看似保存成功实际未落库 |
| 日志告警"数据源顺序里有无效源名" | 源名须为小写：javbus/javdb/javlib/dmm/fc2/missav（1.4.1 起自动 lower 归一化，大小写混用不再报错）；源域名值首尾的 Markdown 反引号由 `base.base_of()` 自动剥离 |
| 目录禁用后还能搜到里面的视频 | 1.4.1 已修复：此前只做了"禁用不删数据"，查询端未过滤；现 `/videos`、`/jav`、幸运骰子均排除禁用目录（数据保留，仅不展示）。回归断言：`/videos total == 库总数 − 禁用目录视频数` |
| 设置里的"隐藏已看完"无效 | 功能从未被消费（仅设置行无读取方），1.4.1 已按需求移除该设置行 |
| 忘记密码 | 见操作手册 §1；或工厂重置 |

**日志**：`data/logs/mediaboss.log`（含时间戳/级别/线程名）；清除日志不影响运行。

## 8. 版本升级

1. 备份 `data/mediaboss.db`。
2. 用新版 `app/` + `server.py` 覆盖旧目录（保留 `data/` 与 `config.toml`）。
3. 启动，数据库结构自动迁移（`user_version` 递增），无需手动操作。
4. 浏览器如出现样式异常，`Ctrl+Shift+R`（服务端已配置自动缓存失效，通常无需）。
